## Rules
1. **Visual-only.** Do not change game logic, economy numbers, IAP/subscription/ads logic, backend calls, analytics events, routes, persistence, cubit/provider APIs. Every button/feature/state that exists today must still exist and work — restyle it. If a mock omits something the screen has, keep it and style it with the system.
2. **Port, don't patch.** Rewrite the screen's widget tree on the new system. Remove usages of the old system in your files: `package:.../ui/design.dart` widgets (`CommandScaffold`, `GlassPanel`, `HoloCard`, `NeonButton`, `HudChip`, `StarfieldBackground`, `LaunchEmblem`, `HoloLogo`, `AppBackground`), `GameTheme` colour getters (`neonPrimary`, `accentColor`, `textMuted`, …) for UI colouring, `GameTypography`, `Orbitron`/`Rajdhani` fonts, `flutter_animate` neon glow/shimmer effects, `BoxShadow` glows, glassmorphism/`BackdropFilter` (except the pause scrim), raw `Colors.*` accents (amber, purple, cyan, redAccent…), emoji used as icons, Material `Icons.*` (use `Symbols.*_rounded` instead). It is fine to keep *reading* the `GameTheme`/`ThemeCubit` state where logic needs it (e.g. passing a theme id into a purchase call, showing a theme's preview swatch in the store).
3. **Import only** `package:cosmo_strike_flutter_app/ui/cs.dart` for the design system. It exports tokens (`CsColors`, `CsGradients`, `CsRadius`, `CsMotion`, `CsSpace`), the responsive helpers (`context.cs`, `context.type`), `Symbols` (Material Symbols — always use the `_rounded` variants; filled is the theme default), and all components. Read every file in `lib/ui/cs/` and `lib/theme/cosmo_theme.dart` before you start — they are short. Reference implementation of the system in a real screen: `lib/screens/home_screen.dart` and `lib/screens/loading_screen.dart`.
4. **Do NOT edit** files outside your assignment, and never edit `lib/ui/cs/*`, `lib/ui/cs.dart`, `lib/theme/*`, `pubspec.yaml`, router, or main.dart. If you need a new reusable component, build it as a private widget in your own file and mention it in your final report (the lead may promote it). Other agents are editing other screens concurrently in the same working tree — **do not run git commands that modify state** (no commit, checkout, stash, reset, add). Read-only git (`git diff -- <your files>`) is fine.
5. **Responsive (critical).** The app is landscape only and must look designed on: small phone 640×360dp, typical Android/iPhone ~850–930×390–430dp (with a notch on one side), Android tablet ~1280×800dp, iPad 11" 1194×834dp and iPad 13" 1366×1024dp.
   - Size everything through `context.cs` (`cs(16)` scales a design-frame px value; `cs.s` is the factor ~0.72–1.4) and `context.type` (pre-scaled type scale: `hero`, `scoreGiant`, `title`, `section`, `hudScore`, `statValue`, `rowTitle`, `body`, `button`, `nav`, `label`, `micro`, plus `display(size, …)` and `mono(size, …)`). Never hard-code font sizes or paddings in raw px.
   - Standard screen = `CsScaffold(title: 'CAMPAIGN', trailing: [CsMeta('…')], body: …)` → body is usually `CsSplit(left: summary column, right: list/grid)`. Use `cs.isTablet` / `cs.isCompact` for layout variants when useful (e.g. more grid columns on tablet, trimming secondary copy on compact).
   - Tablets are much taller relative to width: distribute vertical space with `Expanded`/`Spacer`/`MainAxisAlignment` — don't leave content stuck in the top 50% of an iPad. Lists can scroll; side summary columns should not (use `CsFitColumn` or `FittedBox(scaleDown)`).
   - No overflow anywhere (no yellow/black stripes), no clipped text (use `maxLines` + ellipsis or FittedBox scaleDown for big numbers like 1,000,000+ and long usernames), tap targets ≥ 44dp, nothing under notches (CsScaffold handles SafeArea).
6. **Visual language.** Near-black canvas; hairlines (`CsHairline`, `CsColors.hairline`) instead of cards; bordered `CsTile` only for grids; ONE white primary pill (`CsButton.primary`) per screen, secondary = `CsButton.secondary`, tertiary = `CsButton.text`, premium/upsell = `CsButton.premium` (gold). Prism (`CsPrismText`, `CsPrismRing`, `CsGradients.prism`) only on the 1–2 things that matter on the screen (current item, your rank, the one key word in the headline, a hero progress bar). Semantic colours: mint = success/complete, gold = coins/reward/premium, pink = danger/enemy/game-over, violet = XP, cyan = info. Mono uppercase labels (`CsLabel`, `CsMeta`, `type.label/micro`) for captions/stats/timers; Syne for headings/titles/buttons. Big Syne 800 headline per screen.
   Use `showCsDialog` + `CsDialog` for dialogs (replace `showDialog`/`AlertDialog`/bottom sheets — bottom sheets are awkward in landscape), `showCsConfirm` for confirms, `showCsToast` instead of SnackBars, `CsLoadingState`/`CsEmptyState`(.error/.offline) for states, `CsSegmented` for tabs/filters, `CsListRow` for list rows, `CsStatGrid` for stat blocks, `CsAvatarRing` for avatars, `CsChip` for tags, `CsCoins` for coin amounts, `CsStars` for star ratings, `CsProgressLine` / `CsGoalLine` / `CsRingProgress` for progress.
   Motion: 120/200/320ms with `CsMotion.standard`; press = scale 0.97 (CsPressable/CsButton do it). No looping glow/shimmer animations.
7. Copy: keep existing strings/semantics; you may shorten labels to fit the mono-uppercase style but don't drop information.
8. **Quality bar:** after editing, run `flutter analyze <each file you changed>` from the app root until "No issues found!". Remove imports that become unused. Do not leave dead code or commented-out old UI.
